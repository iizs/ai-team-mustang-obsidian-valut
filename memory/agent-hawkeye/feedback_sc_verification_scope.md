---
name: SC 검증 범위 한계 — 엔드투엔드 통합 흐름
description: 정적 코드 분석만으로는 frontend↔backend 통합 흐름의 누락(엔드포인트 부재, 환경변수 미설정 등)을 잡을 수 없다. SC 검증 시 이 한계를 인식하고 보고에 명시할 것.
type: feedback
---

SC 기반 정적 코드 검증은 컴포넌트별 구현 존재만 확인한다. 컴포넌트 간 통합 흐름(예: frontend가 호출하는 엔드포인트가 backend에 실제로 존재하는지, 환경변수가 통합 흐름에서 올바르게 작동하는지)은 정적 검증으로 잡히지 않는다.

**Why:** Sheska Phase 3 검증(2026-05-07)에서 SC-15, SC-18, SC-25 등을 모두 PASS 처리했지만, 실제 실행 시 다음 누락이 드러남:
- `GET /api/users/me` 엔드포인트가 backend에 부재 (frontend는 호출하지만 backend 라우트 없음)
- `frontend/.env.local`의 `NEXT_PUBLIC_API_URL` 미설정으로 프론트엔드가 backend로 요청을 못 보냄
- 초기 Admin seeding 스크립트 부재 (SC-3은 "Admin이 사용자 생성"만 다루고 첫 Admin 생성은 누락)

이런 누락은 SC가 "기능 단위"로 작성되어 있고 검증도 코드 존재 확인 수준에서 멈췄기 때문에 발생.

**How to apply:**
- SC 작성 단계: "통합 흐름" SC를 명시적으로 추가 검토 (예: "로그인 후 사용자 정보 조회 → 보호된 페이지 진입까지 동작")
- SC 검증 단계: 정적 검증으로 PASS 처리 시 보고서에 "정적 코드 검증 기준; 엔드투엔드 실행 검증은 별도"임을 명시
- 가능하면 통합 테스트 존재 여부도 SC 검증 항목에 포함시킬 것
- 이상적으로는 `docker compose up` 또는 dev 서버 기동 후 핵심 사용자 흐름(로그인 → 조회 → 제출)을 한 번 실행해보는 단계 추가
