## 브레인스토밍 메모 (2026-04-19)

### 배경 / 문제의식

AI를 팀에 도입하면서 생긴 새로운 숙제:
> **사람 간의 암묵적 소통을 텍스트로 만들어야 AI가 따라올 수 있다.**

기존에는 대화로 해결하던 것들이, AI 도입 이후엔 모두 텍스트 산출물로 남겨야 함.
→ 기획자·디자이너에게 GitHub 사용 교육 중 (에이전트가 읽을 수 있는 공유 저장소 확보 목적)

### 현재 팀의 공유 레이어

| 도구 | 역할 |
|------|------|
| **두레이** | 태스크 관리 (GitHub Issues 역할, API 있음 → 스킬로 연동 가능) |
| **GitHub** | 산출물 관리 (코드, 문서) |
| **메시지 채널 (Discord)** | 흐름 + 의사결정 공간 (고민 중인 레이어) |

### 통합 채널의 역할

1. **교차점 의사결정** — 기획/디자인/개발이 서로 영향을 주는 결정을 함께 보는 공간
2. **매니저 가시성** — 대화에 끼지 않아도 전체 업무 흐름 파악 가능 (채팅형 대시보드)
3. ~~에이전트 간 직접 협력~~ — 현 시점엔 핵심 아님, 보류

### 핵심 인사이트

> **각 팀원이 자신의 로컬 에이전트를 메시지 채널에 참여시킬 수 있다.**

- 기획자는 기획 에이전트, 디자이너는 디자인 에이전트, 개발자는 개발 에이전트를 같은 채널에 연결
- 에이전트가 별도 리모트 서버 없이 각자 로컬에서 Discord에 붙으면 됨
- 채널 대화 자체가 에이전트들의 공유 컨텍스트(메모리)가 됨
- 미팅에 노트북 들고 들어가듯, 자신의 에이전트를 데리고 들어가는 방식

온보딩 흐름:
> Discord 봇 토큰 발급 → Claude Code Discord 플러그인 설정 → 채널 초대

### 미결 허들

- **Claude Code 외 에이전트가 필요한 직군 존재** — 디자인처럼 다른 AI 도구를 쓰는 경우, 동일 구조 적용 어려움
