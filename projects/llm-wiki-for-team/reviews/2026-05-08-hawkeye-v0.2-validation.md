## Advisory 관찰

**SC-37 race condition (비블로킹)**
- `users.py:106-116` (role update), `137-147` (active update) — `_active_admin_count()` 호출과 commit 사이 시간차
- 영향도: 동시 다중 admin demote 요청 시 마지막 admin 보호 우회 가능 (확률 매우 낮음, 내부 운영 위주이므로 실제 위험 거의 없음)
- 권장: v0.3+에서 `SELECT ... FOR UPDATE` 또는 명시적 트랜잭션 lock으로 강화. SQLite 직렬화 특성상 현재도 사실상 보호되지만 명시 구현이 더 깔끔.
- Breda가 사전에 동일 우려 짚었음 — 이미 인지된 상태.

## 사후 발견 (Hawkeye 검증 후, Kirin 실사용 시)

**DB 스키마 마이그레이션 누락 (Blocking 가능성, v0.3 백로그)**
- `User` 모델에 `created_at` 컬럼 추가됐으나 SQLite 기존 DB 스키마는 v0.1 그대로
- SQLAlchemy `create_all`만 쓰는 구조 → 기존 인스턴스에서 SELECT 시 컬럼 미존재 에러
- v0.2 검증은 mock 기반 신규 DB로 진행되어 통과했으나, 실 운영 환경에서 **로그인 흐름 깨짐**
- Kirin 회피: DB 삭제 + reseed (B 옵션)
- 근본 대응: alembic 도입 또는 `inspect → ALTER` 자동 적용 — v0.3+
