## Advisory 처리 결과

**A. SC-54 — `git rm` 표현 차이**
- SPEC 본문: "git rm <target> 실행"
- 실제: `target.unlink()` + `commit_changes(removed=...)` → `repo.index.remove(working_tree=True)`
- **기능 동등**. 결과적으로 git에서 파일 사라지고 commit됨.
- 처리: SC-54 본문에 "구현 방식은 `git rm` 또는 `unlink + repo.index.remove(working_tree=True)` 모두 허용 (결과 동등)" 추가 → 표현 완화

**B. SC-58 — WIKI_COMMAND graceful degrade 부재**
- SPEC 본문: "graceful degrade는 INGEST와 동일 (SC-45)"
- 실제: `run_wiki_command`에서 JSON 파싱 실패 → 즉시 `ValueError` → Job FAILED. legacy fallback 시도 없음
- **설계 의도 정합**: INGEST는 사용자 임의 source라 legacy 형식 출력 가능성이 의미 있음. WIKI_COMMAND는 우리가 prompt 통제 → legacy 의미 없음
- 처리: SC-58 본문을 "JSON 파싱 실패 시 즉시 Job FAILED + LLM 출력 snippet `error_msg` 보존. legacy fallback 미적용 (INGEST와 다른 정책)"으로 변경
