## 목표

Ingest 파이프라인이 **기존 위키 구조를 인지하고 분해 plan을 출력**하도록 한다. 같은 주제 중복 페이지 발생을 줄이고, 향후 분리/통합(merge/supersede) 도입의 기반을 마련한다. 추가로 환경 초기화 스크립트를 도입해 운영·테스트 사이클을 빠르게 한다.

## 환경 초기화 스크립트 명세

**파일**: `backend/scripts/init_env.py` (`seed_admin.py` 삭제)

**동작**:
- Interactive prompt 기반, 환경변수 또는 인자가 있으면 그 값을 default로 미리 채움
- DB 스키마 (`create_all` — 없을 때만)
- Source store 디렉토리 생성
- Wiki store 디렉토리 + git init + `index.md`/`log.md`/`_sheska.yaml` 초기화
- Admin 계정 생성 (이메일/패스워드)

**옵션**:
- `--reset` — DB 파일 + source store + wiki store 모두 삭제 후 재생성 (테스트용)
- `--admin-email`, `--admin-password` — interactive prompt 기본값 채우기
- `--non-interactive` — 모든 값을 인자/환경변수에서 가져오고 prompt 생략 (CI 등)

**환경변수 fallback**:
- `INITIAL_ADMIN_EMAIL`, `INITIAL_ADMIN_PASSWORD` — interactive 기본값 또는 non-interactive 모드 입력

## Plan 스키마 (ADR-0011 발췌)

```json
[
  {"action": "create",
   "page_path": "<kebab-case>.md",
   "content": "<full markdown including frontmatter>"},
  {"action": "merge_into",
   "target": "<existing-page>.md",
   "merged_content": "<full new content>"},
  {"action": "supersede",
   "target": "<existing-page>.md",
   "reason": "...",
   "new_content": "<full new content>"}
]
```

Phase A에서는 `create`만 실행. 나머지는 `log.md`에 "skipped (phase A)" 표시.

## 회고

### 잘 된 점

- **합동 검토 효율**: Breda + Hawkeye 동시 SPEC 검토로 모호 항목 ~15건을 셋이 흡수, Kirin 결정은 4건만 에스컬레이션. v0.2 패턴 정착.
- **시간 추정 적중 (코드 작업 기준)**: Realistic 55-70분 → 실제 wall-clock ~50분 (best 근접).
- **graceful degrade 안전망의 가치**: JSON Plan 도입 + legacy fallback 유지 → 회귀 risk 거의 0. 핫픽스 시리즈 도중에도 기존 mock 테스트 PASS 유지.
- **`init_env.py` 도입 효과 즉시 확인**: 테스트 사이클 + B-14 (DB 마이그레이션) 회피책으로 운영 가치 높음.

### 개선할 점 / 발견된 가장 큰 이슈

**🚨 Prompt 로드 버그 — v0.1부터 잠재된 silent failure가 v0.3 실사용 단계에서 드러남**

- 증상: `pipeline._load_prompt`가 파일 못 찾으면 빈 문자열 silent return → Anthropic은 `system: text content blocks must be non-empty`, Ollama는 empty system + FINAL REMINDER만으로 평론형 응답
- **의미**: v0.1~v0.2 회고에서 "Gemma instruction following 약함"으로 평가했던 모든 결론이 무효 — 그동안 prompt가 LLM에 도달하지 못한 상태였음
- 자세한 회고: [reviews/2026-05-08-prompt-load-bug-postmortem.md](../reviews/2026-05-08-prompt-load-bug-postmortem.md)

**📛 LiteLLM Ollama provider 호환성 버그**
- v0.3 결정에서 옵션 A (`response_format` 통일) 채택 → 실측에서 Ollama가 `KeyError: 'arguments'` (`ollama.py:566`)
- 1차 우회 (`format="json"` 분기) → 같은 에러
- 2차 우회 (Ollama JSON 강제 자체 미사용) → 정상 동작
- **임시 조치**. 백로그 [B-21](../backlog.md#b-21-ollama-llm-호환성-우회-제거-경로)로 추적, ADR-0011 본문에 운영 변경 흐름 명시

**그 외:**
- `init_env.py` smoke test에서 Breda가 실수로 Kirin DB 삭제 → 사용자 환경 영향 작업은 사전 알림 필수 (Breda 메모)
- CORS / 외부 접근 / pydantic_settings 호환성 등 환경 설정 이슈가 v0.3에서 한꺼번에 드러남 — v0.4에서 환경 가이드 보강 가치
