# v0.4 — Agentic Wiki Operations + Backlink Index

## 기간 / 상태

2026-05-14 ~ 2026-05-15 / **Done**

## 목표

위키 작업을 정적 Plan 모델에서 **agentic loop**(LLM이 도메인 tool을 반복 호출)로 전환한다. 다중 페이지 작업 자연 처리 + 사용자 의도 적중도 ↑. Backlink 인덱스를 frontmatter에 도입해 표제어 변경/병합 시 영향 분석 가능.

## 회고

### 잘 된 점

- **사전 합동 검토 + Kirin 4건 결정 패턴 정착**: 큰 변경(agentic 전환)임에도 셋이 명세 ~15건 흡수 → 핵심만 Kirin 에스컬레이션. v0.2~v0.3 패턴이 이번에도 그대로 작동.
- **Anthropic-only 단순화 결정 (Kirin)** — fallback 코드 짊어지지 않고 v0.4를 agentic 가치 검증에 집중. v0.5+에서 OllamaNativeAdapter로 복귀할 명확한 경로 보존.
- **B 시작 → D refactor 전략 (Kirin)** — Claude Agent SDK lock-in 피하면서 Anthropic SDK 직접 사용. v0.5에서 adapter 추출 가능한 응집도로 코드 작성.
- **patch_page unified diff 도입 (Kirin)** — search-replace 대신 표준 diff 패턴 채택으로 출력 토큰 절약 + 표준 도구 호환성.
- **Hawkeye 검증의 BLocking 잡기** — SC-71/SC-78이 mock 통과했음에도 SPEC 의도와 차이 발견. Hawkeye 정적 분석 가치 재확인.
- **실사용 → 핵심 통찰 → ADR로 격상 (rename_page 사례)** — 실측에서 Index-Trust + Lint-Repair 원칙(ADR-0016) 도출. 운영 회고가 자연스럽게 영구 문서로 진화.

### 핫픽스 시리즈로 드러난 약점

v0.4는 본 구현 끝난 후 **10건 가까운 핫픽스**가 필요했음. 패턴 분석:

1. **테스트 격리 부족** (MagicMock 디렉토리, SC-67 mock-only 검증): mock이 실제 부수효과를 시뮬레이션 못 함. SC가 "결과"가 아닌 "구현 존재"로 검증된 case가 또 드러남.
2. **운영 환경 통합 이슈** (greenlet 누락): 단일 노트북에서 우연히 동작하던 의존성이 새 환경에서 깨짐. requirements.txt 명시성 부족.
3. **LLM 동작 가정의 부정확성** (max_tokens 단일 호출 spike, hallucinated created 날짜): mock 테스트로는 못 잡는 실 모델 행동 패턴.
4. **운영 한도 misalignment** (rate limit 30k TPM vs 우리 agentic 호출 패턴): tier 1 한도가 v0.4 가정과 안 맞음 → caching + retry로 본질 대응.

핫픽스 자체는 빠르게 흡수했지만, **SC 작성 시 "실 운영 시나리오"까지 가정해야 한다**는 교훈 재확인.

### 개선할 점

- **백링크 인덱스 일관성**: 자동 갱신 hook이 모든 경로(write_page, patch_page, delete_page, rename_page)에서 동작해야 하는데 v0.3 이전 페이지에는 부재 → `init_backlinks.py --rebuild-backlinks` 마이그레이션 수동 트리거 필요. Lint(B-6)가 정착되면 자동화 가능.
- **운영 가시성**: usage 로깅이 v0.4 본 구현에 빠짐 → 핫픽스로 추가. 비용 telemetry(B-22)도 v0.5+ 정식 백로그.
- **LLM 호출당 입력 spike**: read_source 결과 한 번에 30k+ → tier 1 한도 단일 호출 초과. 향후 source chunking 또는 read_source 결과 cache_control 추가 검토.
