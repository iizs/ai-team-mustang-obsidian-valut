# v0.4 — Agentic Wiki Operations + Backlink Index

## 기간 / 상태

2026-05-14 ~ ? / **Planning** (요건 검토 중)

## 목표

위키 작업을 정적 Plan 모델에서 **agentic loop**(LLM이 도메인 tool을 반복 호출)로 전환한다. 다중 페이지 작업 자연 처리 + 사용자 의도 적중도 ↑. Backlink 인덱스를 frontmatter에 도입해 표제어 변경/병합 시 영향 분석 가능.

## 스코프

**포함:**
- **Agentic loop** ([ADR-0013](../decisions/0013-agentic-loop-provider-adapter.md))
  - Anthropic SDK 직접 사용 (Claude Agent SDK 아님)
  - INGEST + WIKI_COMMAND 통합 (내부적으로 동일 agentic 흐름, UI는 분리 유지)
  - max_iterations / max_tool_calls / timeout / 이상 패턴 감지 안전장치
  - Progress checkpoint (`Job.payload.steps`) + 사용자 취소
- **Tool 카탈로그** ([ADR-0014](../decisions/0014-tool-catalog-and-commit-log.md))
  - `get_index`, `read_page`, `read_source`, `search_pages`, `write_page`, `patch_page`, `delete_page`, `get_backlinks`
  - 매 write/patch/delete tool 호출 = 1 git commit (현재). 1 액션 = 1 commit는 v0.5+
- **Backlink 인덱스** ([ADR-0015](../decisions/0015-backlink-frontmatter-index.md))
  - frontmatter `backlinks` 필드 + 시스템 자동 갱신
  - 마이그레이션 스크립트 (기존 위키 1회 스캔)

**제외 (v0.5+):**
- Lint job type 실제 구현 (인프라는 자연 지원, 트리거만 추가하면 됨)
- Provider Adapter 추상화 (B → D refactor는 v0.5)
- Ollama agentic 모드 (v0.4 동안은 v0.3.1 흐름 유지)
- Dry-run 모드 (취소 안전망으로 충분, 미룸)
- 1 액션 = 1 commit 묶음 (v0.4는 매 step commit)
- Per-page history 별도 파일 (git log로 해결)
