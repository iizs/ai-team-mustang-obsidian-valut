# ADR-0009 — Edit Flow: 단일 페이지 컨텍스트

- **상태**: Accepted
- **결정일**: 2026-05-06
- **결정자**: Kirin, Roy

## 컨텍스트

사용자 수정 요청을 어떤 단위로 받을지. 초기 SPEC은 "사용자가 수정 요청 텍스트 입력 → LLM이 관련 페이지 찾아 수정"으로 모호했음. 페이지 수가 많아지면 전체를 LLM context에 못 넣고, 페이지 선택 자체가 별도 LLM 호출이 됨.

## 검토한 옵션

1. **2단계 LLM 호출**: 페이지 목록 + frontmatter 전달 → 대상 페이지 선택 → 선택된 페이지 수정
2. **단일 페이지 컨텍스트**: 사용자가 특정 위키 페이지 조회 화면 하단 입력창에서 수정 요청 → 해당 페이지만 수정

## 결정

**단일 페이지 컨텍스트(2번) 채택.** EDIT Job payload에 `page_path` 포함.

## 근거

- 2단계 LLM 호출은 LLM 비용 2배 + 잘못된 페이지 선택 리스크
- 사용자가 어느 페이지를 수정하려는지 명확히 지정하는 게 의도 정확도 높음
- UI 흐름이 자연스러움: 페이지 보다가 "이 부분 수정해줘"
- 다중 페이지에 걸친 요청은 다른 방법(예: 일괄 처리, 워크플로우)이 필요 → MVP 범위 외

## 트레이드오프

- 사용자가 수정하려는 내용이 어느 페이지에 있는지 모를 때 불편
- v0.2에서 "위키 검색 + 결과에서 페이지 선택" UX 추가 검토
