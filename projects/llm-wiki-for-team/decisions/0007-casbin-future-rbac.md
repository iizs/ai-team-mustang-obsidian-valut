# ADR-0007 — 권한 관리: MVP 직접 구현, v0.2+ Casbin 확장 가능성

- **상태**: Accepted (방향성)
- **결정일**: 2026-05-06
- **결정자**: Kirin, Roy

## 컨텍스트

MVP 권한은 Admin/Member 2-role뿐이지만, 운영 중 권한 세분화(원본 폴더별, 페이지별, 그룹별 등) 필요성이 발생할 가능성 높음. 처음부터 외부 라이브러리를 도입할지, 직접 구현 후 필요 시 마이그레이션할지.

## 검토한 옵션

1. **Casbin** — 오픈소스 권한 관리 라이브러리, RBAC/ABAC/ACL, 정책 파일/DB 분리, FastAPI 통합 쉬움
2. **Open Policy Agent (OPA)** — 정책 Rego 언어, 분산 시스템에 강함 — Sheska 규모엔 과함
3. **Keycloak** — SSO + 권한 올인원, 별도 컨테이너 필요 — 운영 부담

## 결정

**MVP는 간단한 role 컬럼(Admin/Member) 직접 구현. v0.2+에서 권한 원자화 시 Casbin 확장 가능성을 염두에 둔 설계.**

## 근거

- 2-role만으로는 라이브러리 도입 비용이 크지 않은 직접 구현으로도 충분
- Casbin은 정책 레이어 교체 형태로 마이그레이션 가능 — 기존 코드 구조 크게 안 바꿔도 됨
- 처음부터 Casbin 도입 시 학습/디버깅 비용

## 후속 작업

- Auth 컴포넌트의 권한 검증 함수를 명확히 분리 (`require_admin` 등) → 마이그레이션 시 교체점 명확화
