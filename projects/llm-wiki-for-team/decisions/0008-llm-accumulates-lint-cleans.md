# ADR-0008 — "LLM은 축적, 삭제 판단은 Lint" 원칙

- **상태**: Accepted
- **결정일**: 2026-05-06
- **결정자**: Kirin, Roy

## 컨텍스트

원본 파일이 교체되거나 사용자 수정 요청이 들어왔을 때, LLM에게 "기존 위키 내용 삭제"를 맡길지 결정 필요. 초기 설계는 INGEST를 신규/교체로 분리하고 `is_update` 플래그로 처리하려 했음.

## 결정

**INGEST/EDIT 모두 단일 플로우로 처리. LLM은 새 내용 추가/보강만 한다. 원본에서 빠진 내용의 정리는 Lint(v0.2+) 단계에서 처리.**

`is_update` 플래그 폐기.

## 근거

- 같은 path로 동작하는 이유:
  - 동일 내용 → 위키에 이미 존재, 변동 없음
  - 추가된 내용 → LLM이 새 페이지 생성 또는 기존 페이지 보강
  - 빠진 내용 → 위키에서 즉시 제거되지 않음 → Lint에서 처리
- Karpathy 컨셉의 핵심
- LLM이 "삭제할 내용"을 판단하는 건 위험. 사용자 의도를 잘못 해석한 삭제는 복구 어려움
- Lint는 별도 단계로 두면 정책(언제, 어떤 기준으로 정리)을 분리해 통제 가능

## 트레이드오프 (Known Limitation)

- v0.1에서는 Lint가 없으므로 원본 교체 시 빠진 내용이 위키에 잔존할 수 있음
- 사용자가 직접 Edit 요청으로 수동 정리해야 함
- v0.2에서 Lint 도입으로 해소 예정
