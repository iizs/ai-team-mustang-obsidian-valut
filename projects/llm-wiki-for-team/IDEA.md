# llm-wiki-for-team

**서비스 이름: Sheska** (Sheska: llm-wiki for team)

팀을 위한 LLM 위키 — AI 에이전트가 참조할 수 있는 팀/서비스 지식 베이스 설계 및 구축.
일종의 솔루션/제품 개념으로 접근.

배경: cowork 프로젝트의 Knowledge Base 논의에서 파생.

---

## 브레인스토밍 메모 (2026-05-05)

### 컨셉의 출발점

Andrej Karpathy의 LLM Wiki 컨셉을 팀 협업 도구로 확장.

> 원본 자료는 사람이 주입하고, 정리/관리/업데이트는 LLM이 담당.

개인 용도로는 완벽하지만, 팀 협업 도구로 쓰려면 추가로 해결할 것들이 있다.

---

### 핵심 구조

```
원본 자료 (Source of Truth)
  ↓ LLM이 읽고 정리
Knowledge Base (KB) — 구조화된 뷰
  ↓ Git 저장소
로컬 에이전트가 참조
```

---

### 원본 LLM Wiki 컨셉의 단계

| 단계 | 설명 |
|------|------|
| **Ingest** | 원본 자료 투입 |
| **Organize** | LLM이 KB로 정리 |
| **Lint** | 주기적 헬스체크 및 정합성 교정 (`Periodically, ask the LLM to health-check the wiki`) |
| **Query** | 에이전트/사람이 KB 조회 |

팀 협업 도구로서 추가되는 레이어: **권한 관리 + UI**

---

### 허들 및 해소 방안

| 허들 | 해소 방안 |
|------|----------|
| **관리/업데이트 책임** | LLM이 담당, 사람은 원본 자료 큐레이터 역할 |
| **권한 관리** | 기능으로 해결. 팀 내부 용도라면 전원 개방도 가능 |
| **원본 자료 투입** | NotebookLM형 UI — 파일 업로드, URL 입력, 텍스트 직접 입력 |
| **품질 관리** | Source of Truth 기반 재생성 + Lint 주기 실행 |
| **원본 수정** | 원본 replace → Lint에서 KB 반영 |
| **원본 삭제** | 원본 삭제 → Lint에서 KB 정리. Soft delete(trash)는 선택적 UX |
| **사람의 가시성** | 위키형 UI로 해소 |
| **KB 편집권** | 사람은 LLM에게 수정 요청만. 직접 편집 불가 (흐름 일관성 유지) |

---

### 에이전트 연동

KB를 각 에이전트의 로컬 환경에 전달하는 방법:

| 방법 | 특징 |
|------|------|
| **Git checkout/pull** | 자동화 가능, 버전 히스토리 포함, 주기적 동기화 |
| **Zip 다운로드** | 수동, 간단 |

→ 두 방법 모두 제공 (솔루션 개념이므로 다양한 환경 지원 필요)

에이전트는 로컬에 받은 KB를 CLAUDE.md 경로 참조 등으로 활용.
우리 팀의 CONSTITUTION.md/WORKFLOW.md Git 관리 방식과 동일한 패턴.
