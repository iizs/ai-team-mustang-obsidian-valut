# sns-publishing

_2026-09-27 착수 · 담당: Falman_

Kirin이 쓴 글을 Falman이 검토·번역하고 여러 SNS에 발행하는 흐름. 원고와 진행 상황은 Dooray `SNS-Publishing` 프로젝트(`4429251819650654485`)에서 관리한다. 발행은 API 대신 Claude in Chrome 브라우저 제어로 한다. 이전에 API 방식은 토큰 만료와 플랫폼 제약이 많았기 때문이다.

## 공통 원칙

- 브라우저: Claude in Chrome, **"Chrome for Falman" 프로필**만 사용. 세션은 `claude --chrome --remote-control falman`으로 시작.
- 로그인: 되어 있다고 가정한다. 로그인 화면이나 본인 확인 요구를 만나면 **즉시 중지하고 Kirin에게 리포트**한다. Falman은 로그인하지 않는다 (저장된 비밀번호 자동완성 포함).
- 발행 승인: 세션 채팅(터미널 또는 Remote Control)으로만 받는다. 승인 목록에 없는 게시는 하지 않는다.
- 플랫폼별 발행 절차는 Claude Code 스킬로 분리한다 (`agent-falman/.claude/skills/publish-<platform>/`).

## 플랫폼 스킬

| 스킬 | 상태 |
|---|---|
| `publish-facebook` | 임시저장·예약 검증 완료, 즉시 게시 미검증 |
| `publish-linkedin` | 드래프트 검증 완료 (2026-09-30, SNS-Publishing/6) |
| `publish-wordpress` | 드래프트 검증 완료 (WordPress.com) |

## publish-facebook 스펙

**입력**
- 본문 텍스트 (필수)
- 이미지 파일 경로 목록 (선택, 로컬 경로. Dooray 첨부는 `task-file-download`로 먼저 받는다)
- 공개 범위: 기본 `전체 공개`, 테스트 중에는 `나만 보기`

**계정 구조**
- 하나의 로그인으로 두 프로필을 오간다. 전환은 화면 오른쪽 위 프로필 메뉴에서 한다.
  - `Choi Kirin`: 개인 프로필. **Falman이 게시하지 않는다.**
  - `Choi Kirin / 최기린`: 공개 페이지. **Falman의 게시 대상.**
- 게시 전 현재 활성 프로필이 `Choi Kirin / 최기린`인지 반드시 확인하고, 아니면 전환한다.

**절차**
1. facebook.com 접속 → 로그인 상태 확인 (아니면 중지·리포트)
2. 활성 프로필 확인 → 필요하면 `Choi Kirin / 최기린`으로 전환
3. 게시물 작성창 열기 → 본문 입력 → 이미지 첨부
4. 공개 범위 설정 (테스트: `나만 보기`)
5. 게시 전 입력 내용과 프로필, 공개 범위를 스크린샷으로 확인
6. 게시 → 게시물 URL 확보
7. 결과(URL, 프로필, 공개 범위) 리포트. Dooray 태스크에서 실행한 경우 댓글로 기록

**중지 조건 (리포트 후 대기)**
- 로그인 안 됨, 본인 확인·보안 점검 요구
- 프로필 전환 실패 또는 활성 프로필을 확정할 수 없음
- 요청한 공개 범위를 선택할 수 없음 (특히 테스트 중 `나만 보기`가 없을 때 전체 공개로 올리지 않는다)
- 예상과 다른 UI로 절차를 진행할 수 없음

## publish-wordpress 스펙

**대상**: WordPress.com 블로그 `https://kirinchoi.wordpress.com/wp-admin/`. 영문으로 운영한다.

**입력**
- 원고: **영문 번역본** (필수). 보통 번역 태스크의 최종 번역본을 지정받는다.
  - 한글 원고로 업로드를 지시받으면 진행하지 않는다. 태스크에 "번역본을 지정해달라"고 댓글을 달고 Kirin에게 돌려보낸다.
- 제목: Kirin이 제공한다. 없으면 Falman이 하나 추천해 그 제목으로 드래프트를 만들고, 추천한 제목임을 리포트에 밝힌다.
  - 원고 첫 줄이 제목(`# ...`)이면 제목 입력칸으로 옮기고 본문에서는 뺀다.
- 이미지: 선택. 첨부를 지시받은 경우에만 사용한다.
- 카테고리, 태그, 이미지 대체 텍스트: 태스크에 지정된 경우에만 넣고, 없으면 비워둔다 (2026-09-27 결정).

**범위**: 드래프트 저장까지. 게시는 CLAUDE.md 발행 규칙대로 Kirin이 직접 하거나 세션 채팅으로 지시한다.

**절차**
1. `wp-admin` 접속 → 로그인 상태 확인. 로그인이 풀려 있으면 **중지하고 Kirin에게 로그인을 요청**한다.
2. 이미지가 있으면 먼저 **Media 라이브러리에 업로드**한다.
3. Posts → Add New(글쓰기)로 에디터(블록 에디터)를 연다.
4. 제목 입력.
5. 이미지가 있으면:
   - 업로드한 미디어를 **Featured image**로 지정한다.
   - 본문 **맨 위**에 같은 이미지를 **가운데 정렬** 이미지 블록으로 넣는다. 새로 올리지 않고 Media 라이브러리에서 가져온다.
6. 본문 입력.
7. **Save draft**. 드래프트 목록에서 저장을 확인한다.
8. 리포트: 제목(추천 여부), 이미지 처리 결과, 드래프트 위치를 태스크 댓글로 남긴다.

**중지 조건**: 로그인 풀림, 한글 원고로 지시받음, 이미지 업로드 실패, 에디터 UI가 예상과 달라 진행할 수 없음.

## publish-linkedin 스펙

**대상**: LinkedIn 개인 프로필 `Choi Kirin` (`https://www.linkedin.com/in/choi-kirin/`)의 일반 게시물(post).
- 페이지 `N.I.C.K. the Agent`는 쓰지 않는다 (예전 API 게시용).
- Article 기능은 쓰지 않는다. 긴 글 역할은 WordPress가 맡는다.

**입력**
- 원고: 영문 번역본 (WordPress와 같은 원고).
- WordPress 게시물 URL (필수). LinkedIn 글에는 항상 WP 링크를 붙이므로, WP 글이 먼저 게시돼 있어야 한다.

**글 구성** (Kirin의 기존 게시물 3편에서 확인한 형식, 2026-09-29)
- 글자 수 한도: **3,000자**. 제목, 안내 문장, URL을 모두 포함해 센다 (Kirin 확인).
- 제목: 첫 줄에 항상 넣는다. Kirin이 빼달라고 명시한 경우에만 뺀다.
- 전문을 올릴 때 (3,000자 이내): 구분선 없이 URL만 붙인다.
  ```
  <제목>

  <본문 전체>

  <WP URL>
  ```
- 잘라서 올릴 때 (3,000자 초과):
  ```
  <제목>

  <본문 앞부분, 흥미가 생기는 대목에서 끊고 끝에 " ...">

  ---

  <안내 문장>

  <WP URL>
  ```
  - 자르는 위치: 한도를 넘지 않는 선에서, 다음이 궁금해지는 지점. 문단 경계보다 흥미 유발을 우선한다.
  - 안내 문장: Kirin이 승인한 세 문장을 태스크 번호 % 3으로 돌아가며 쓴다. 매번 승인받지 않는다 (2026-09-29). 목록은 스킬에 있다.
- 공통: 영문, 해시태그 없음, 목록은 `* `, 이미지 업로드 없음. WP URL을 넣으면 LinkedIn이 링크 미리보기 카드(WP 대표 이미지 포함)를 자동으로 붙이고 URL을 `lnkd.in`으로 줄인다.

**드래프트 규칙**
- LinkedIn 일반 게시물 드래프트는 **계정 단위로 한 칸만** 있다. 목록이 없고, 모든 기기·브라우저에서 같은 드래프트가 보인다 (Kirin 확인, 2026-09-29).
- 저장 전에 작성창에 기존 드래프트가 있는지 확인한다. 있으면 **저장하지 않고 중지·리포트**한다. Kirin이 쓰던 글을 덮어쓰지 않기 위해서다.
- 작성창을 닫을 때 "Save this post as a draft?" 창에서 `Save as draft`를 누르면 저장된다. 피드 상단 작성창에 `Draft: ...`로 표시된다.

**범위**: 드래프트 저장까지. 게시는 Kirin이 직접 하거나 세션 채팅으로 지시한다.

**중지 조건**: 로그인 풀림, 기존 드래프트 존재, WP URL 없음(WP 미게시), 한글 원고로 지시받음.

**WP URL 가져오기**: LinkedIn 태스크 본문에 연결된 WP 태스크의 "게시 URL" 댓글에서 가져온다. 없으면 연결된 WP 태스크의 post ID로 `?p=<ID>` 리다이렉트를 확인한다. 그래도 게시 전이면 중지·리포트한다.

### 오케스트레이션 설계 메모 (2026-10-02)

**목표 흐름**: Kirin이 메인 태스크 "[원고] 제목"을 Falman에게 할당 → Falman이 서브태스크를 만들고, 자기가 할 수 있는 단계는 진행하고, Kirin 차례인 단계는 Kirin을 담당자에 추가해 응답을 받는다.

**단계 순서** (오케스트레이션 스킬에 고정, 메인 태스크 본문에는 체크리스트로 표시)
- 교정 → (Kirin OK) → FB 드래프트, 번역
- 번역 → (Kirin OK) → WP 드래프트
- WP 게시 (Kirin) → LI 드래프트
- 각 드래프트 → 게시는 Kirin이 직접 하거나 세션 채팅으로 지시

**hub 이벤트 동작 확인 결과** (Sandbox/19·23, 2026-10-02 — Roy 확인: 정상 동작)
- 댓글·상태 변경 이벤트는 담당자에 들어 있으면 태스크 상태·개별 workflow와 관계없이 즉시 온다.
- `pollDrain`(`"request_origin": "poll"`)은 변화가 있을 때만 4~5분 뒤 한 번 온다. 변화가 없으면 오지 않는다.
- 2026-09-27 /4의 `pollDrain` 반복은 그날 두레이 500 오류의 여파였다.

**그래서 정한 것**
- 담당자 돌려주기 규칙은 두지 않는다. Kirin은 댓글만 달면 된다.
- 서브태스크는 처음부터 다 만들어도 된다. 막혀 있는 동안에는 이벤트가 오지 않는다.
- 막힌 단계를 여는 계기는 앞 단계 서브태스크의 이벤트다. 이벤트가 온 태스크에서 출발해 메인 태스크와 형제 서브태스크를 다시 읽고 다음 단계를 판단한다. 진행 상태를 따로 저장하지 않는다.

**보강 목록**
1. 오케스트레이션 스킬 (위 판단 로직)
2. 교정·번역 스킬화 (맞춤법만 수정 원칙, 번역 톤, v2 댓글 형식)
3. 메인 태스크 템플릿 (대상 플랫폼, 번역 톤, 첨부 이미지, 제목 지정 여부)
4. 두레이 호출 실패 처리 규칙 (아래)
5. 중복 이벤트 처리: 변화 하나에 이벤트가 두 번(즉시 + `pollDrain`) 온다. 마지막 댓글이 이미 처리한 것이면 넘어간다.
6. Kirin 차례 표시: 서브태스크 담당자에 Kirin을 추가한다. Kirin이 댓글을 달면 Kirin 몫 상태는 Falman이 정리한다.

**두레이 호출 실패 처리 규칙** (dooray-skill v0.6 기준, 2026-10-02)

CLI가 하는 것 (`3bf6c2b`): 읽기(GET)는 5xx·타임아웃·연결 오류에 1초→2초 간격 최대 3회 재시도. 쓰기는 서버에 닿기 전 실패만 재시도. 실패 시 stdout은 비고, stderr에 JSON 한 줄 + 종료 코드.

| 종료 코드 | `error` | Falman 대응 |
|---|---|---|
| 0 | — | 성공 |
| 3 | `transient` | CLI가 이미 재시도했으니 바로 반복하지 않는다. 태스크 상태는 그대로 두고 다음 이벤트 때 다시 한다. 반복되면 알린다 |
| 4 | `permanent` | 재시도하지 않는다. 중지하고 알린다 (권한·대상 id·입력 확인) |
| 5 | `uncertain` | 쓰기가 반영됐는지 먼저 확인하고, 안 됐을 때만 다시 실행한다 |
| 1 | `unexpected` | `message`를 보고 판단, 필요하면 알린다 |
| 2 | — | 명령 사용법 오류. 인자를 고친다 |

- 호출 방식: 결과를 파이프로 바로 파싱하지 않는다. 종료 코드를 먼저 확인하고, 실패면 stderr JSON을 읽는다.
- 쓰기 반영 확인용 표시: 서브태스크는 제목 접두어(`[교정]`, `[FB]` 등), 댓글은 첫 줄 형식.
- 알림 경로: 두레이 자체가 안 될 수 있으니 푸시 알림·세션 메시지로 알린다. 진행 상태를 따로 저장하지 않으므로 다음 이벤트가 오면 다시 읽고 이어 간다.
- 2026-09-27 `task-files-list` 500은 두레이 장애 시간대의 일시적 오류였다 (2026-10-02 재시도에서 정상).
- **재시작 후 브라우저 선택 문제**: 재부팅 후 Claude 확장 연결 이름이 "Browser 1/2"로 초기화되고, 여러 프로필이 동시에 연결돼 "Chrome for Falman"(Chrome 프로필 "MacMini")을 구분할 수 없었다. 2026-09-29에는 `switch_browser` 확인 창으로 Kirin이 직접 골라서 해결했다.
  - ✅ 자동 실행 (2026-10-02): LaunchAgent `~/Library/LaunchAgents/net.iizs.chrome-falman.plist`가 로그인 시 `open -na "Google Chrome" --args --profile-directory="Profile 4"`(= "MacMini" 프로필)를 실행한다. 자동 로그인 ON, FileVault OFF. 창을 닫으면 다시 뜨지 않으니 `launchctl start net.iizs.chrome-falman`으로 다시 띄운다.
  - ✅ 확장 정리 (2026-10-02): Claude 확장을 MacMini 프로필에서만 켜고 다른 프로필은 모두 껐다. 연결 목록에 브라우저가 하나만 뜨는 것 확인 (deviceId `18ae36fd…`).
  - ✅ 발행 스킬 3종은 시작 시 연결된 브라우저가 없으면 MacMini 프로필 창을 직접 띄운다.
