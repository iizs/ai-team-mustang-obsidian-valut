## 드레인 전략 이관 · agent-side → receiver-side 폴링

`ScheduleWakeup` gap(09-16 발견, `/loop dynamic` 전용) 을 해결하기 위해 드레인을 서버로 옮기기로 결정. Receiver 에 폴 스케줄러(`app/poller.py`, 기본 10분 주기) 추가 — WS 연결된 각 agent 별로 `TASK_HUB_PROJECT_IDS` public 프로젝트에서 pending 태스크(`registered`, `working`) 조회 후 `hook_event=pollDrain` envelope 로 push. `(agent, post_id) → postUpdatedAt` in-memory dedup 으로 폴 반복 시 skill 재호출 폭풍 방지. Skill 은 notification-driven only 로 축소 — drain phase · 안전망 · 세션 시작 자동 호출 세 개 모두 제거. 배포: `docker compose up -d --build` 완료, `/health` 에 `poll_interval_sec:600` · `poll_delivered:0` 노출. 세션 시작 시 밀린 태스크 확인도 불필요 (다음 폴 tick 에서 자연 회복). Private 프로젝트(`@roy` 등) 는 스코프 밖 — public 만 커버.
