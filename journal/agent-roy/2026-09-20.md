## 드레인 전략 이관 · agent-side → receiver-side 폴링

`ScheduleWakeup` gap(09-16 발견, `/loop dynamic` 전용) 을 해결하기 위해 드레인을 서버로 옮기기로 결정. Receiver 에 폴 스케줄러(`app/poller.py`, 기본 10분 주기) 추가 — WS 연결된 각 agent 별로 `TASK_HUB_PROJECT_IDS` public 프로젝트에서 pending 태스크(`registered`, `working`) 조회 후 `hook_event=pollDrain` envelope 로 push. `(agent, post_id) → postUpdatedAt` in-memory dedup 으로 폴 반복 시 skill 재호출 폭풍 방지. Skill 은 notification-driven only 로 축소 — drain phase · 안전망 · 세션 시작 자동 호출 세 개 모두 제거. 배포: `docker compose up -d --build` 완료, `/health` 에 `poll_interval_sec:600` · `poll_delivered:0` 노출. 세션 시작 시 밀린 태스크 확인도 불필요 (다음 폴 tick 에서 자연 회복). Private 프로젝트(`@roy` 등) 는 스코프 밖 — public 만 커버.

**남은 결정**: 폴 주기 fine-tune (관찰 후).

## 폴 드레인·Funnel 실 검증 · 관찰성 fix

**관찰성 fix**: 폴 배포 직후 tick 이 안 뛰는 것처럼 보임 → 실은 `_tick` 이 pending 0건일 때 아무 로그도 안 남긴 탓. 매 tick 끝에 `poll.tick {agents, pending, pushed}` 로그 추가 (mustang-hub `af00fdc`). 60s 임시 주기로 실 tick 관찰 확인 후 600s 원복.

**폴 드레인 e2e**: Kirin 이 세션 exit → Sandbox "폴링 테스트" 태스크 생성 → 세션 재시작 (WS 끊긴 사이라 webhook broadcast=0 drop) → 다음 폴 tick 에서 `pollDrain` push → hub skill 자동 호출 → 처리 완결. 설계 목적 그대로 안전망 작동 확인.

**Funnel e2e**: "도메인 변경 테스트" 태스크에서 `postCreated` webhook 만 receiver 도달 안 함 (다른 comment/workflow/user changed 는 정상). 폴 드레인이 1분 26초 후 rescue. 이후 "이벤트 테스트" 태스크에선 `postCreated` 실시간 도달 → 첫 태스크 miss 는 이관 초기 일시적 이슈로 판단 (Tailscale cert warmup 또는 hook 활성화 race 가설). 재발 시 재조사 대상.

**남은 결정**: postCreated first-miss 원인 지속 관찰 · 재발 여부.
**관련**: [[projects/mustang-hub/README]] · mustang-hub `af00fdc`.

## 재부팅 자동 복구 체인 완결 (OrbStack + restart policy + Tailscale)

Mac 재부팅·로그인 후 별도 조작 없이 전체 스택 복구되도록 3중 자동화 확정: (1) Tailscale.app 자체 로그인 시 실행 + `tailscale funnel` config persist (2) `orbctl config set app.start_at_login true` (3) 컨테이너 `restart: unless-stopped` (이미 세팅). 순서 무관 — 각 층이 재시도/복원 매커니즘 보유, 사이 gap 은 폴 드레인이 흡수. 오늘 저녁 macOS 업데이트 재부팅으로 실 검증 예정.

**관련**: [[projects/mustang-hub/README]] "재부팅 자동 복구 체인" 소절 신규.
