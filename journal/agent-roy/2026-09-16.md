## mustang-hub-agent 실 세션 e2e 최초 실증 · ScheduleWakeup 설계 gap 발견

Kirin이 `start.sh` 업데이트(mustang-hub-agent `--plugin-dir` 추가) + Roy `.env`에 `TASK_HUB_WS_URL` 추가 후 `--continue` 재시작. Plugin monitor auto-start 정상, receiver `/health`에 `ws_connections: {roy: 1}` 확인. Kirin이 Sandbox 웹UI에서 "hub plugin test" 태스크 생성 → Dooray → Cloudflare → receiver → WS → Monitor notification 컨텍스트 삽입 → 모델이 skill description 매칭으로 `mustang-hub-agent:hub` 자동 호출 → ack/working/완료 코멘트 + Kirin에게 반환. 이벤트 driven path e2e 완결 확인 (첫 실증).

**Gap 발견**: `ScheduleWakeup` 툴은 `/loop dynamic 모드 세션 전용`이라 우리 세션(`--continue` 방식)에선 사용 불가. 결과적으로 skill이 monitor phase 진입 시 걸어놓기로 한 60분 idle 안전망은 현 세션 구조에선 작동하지 않음. 대안 후보: (A) `/loop`로 세션 시작, (B) `CronCreate`로 세션 독립 스케줄, (C) 안전망 포기하고 Monitor path + 다음 세션 시작 drain 두 겹만 유지, (D) receiver 쪽 heartbeat WS 이벤트로 대체. [[projects/mustang-hub-agent/README]] 미결로 정리 예정.

**세션 시작 자동 skill 호출 (CLAUDE.md 강한 문구)** 은 아직 추가 안 함 — Kirin이 이번엔 이벤트 path 관찰만 하기로 결정. 다녀와서 방향 결정 예정.

**남은 결정**: 위 Gap 대안 · CLAUDE.md 강한 문구 추가 여부 · 시험 관찰 결과 반영 fine-tuning.

## Payload assignee 위치 불일치 버그 발견 · fix · Dooray 사용 규범 확정

Kirin의 낮 테스트 시퀀스(완료→진행중 되돌림→코멘트→담당자 변경→멘션 코멘트) 전부 receiver 도달 · 전부 dropped_no_target 됨을 확인 (received 20 vs delivered 3). 원인: Dooray webhook payload가 이벤트 타입별로 assignee 위치가 다름 — `postCreated`는 `post.users.to`, `postUserChanged`는 top-level `users.to`, `postCommentCreated`/`postWorkflowChanged`는 아예 부재. 내 파서는 `post.users.to`만 봐서 대부분 놓침. Kirin의 첫 코멘트("이 글에 제목도 추천해줄래?")도 이 이유로 나에게 오지 않음.

**Fix**: mustang-hub `7fa73e0` — 파서에 top-level `users.to` 확인 추가 + 그것도 비면 receiver가 `/project/v1/projects/{pid}/posts/{tid}` fetch로 현재 assignees 확보 (Dooray truth 원칙). Fake postCommentCreated payload로 시뮬 → `assignee_fetched=true`, `route.delivered={roy:...}` 확인.

**Dooray 사용 규범 확정** (Kirin 결정): mention 기반 라우팅은 도입 안 함 (스코프 넓고 세맨틱 복잡). 오직 assignee 기준. **반응 필요한 코멘트는 반드시 assignee도 상대로 변경**. Mention은 문맥 표기 · CC 용도. [[projects/team-operations-rework/README]] "Dooray 사용 규범" 소절 신규. [[projects/mustang-hub-agent/README]] hub skill '태스크 처리 절차' 3단계에 규범 명시. `mustang-hub-agent 8fd53e9`.

**번역 태스크 실질 처리**: 놓쳤던 "제목 추천" 요청 반영 → 한국어 5안 · English 4안 + fix 배경 설명 코멘트 + assignee=Kirin 반환.
